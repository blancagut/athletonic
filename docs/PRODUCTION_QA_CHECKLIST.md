# Athletonic Production QA Checklist

Scope: Vercel deployment, static site assets, API readiness, domain cutover, and final production QA. Stripe checkout, Stripe webhooks, and payment-mode validation are intentionally out of scope here.

## Deploy Shape

- Project root is the Vercel root.
- Static assets are committed HTML/CSS/JS/data files: `index.html`, `pages/`, `product/`, `assets/`, and `data/`.
- Vercel API Functions live under `api/**/*.js`.
- `vercel.json` sets API max duration plus security/no-cache headers; it does not define a build command.
- Current production deploy assumption: Vercel serves the committed generated files. When catalog or static page generation changes, run generation locally, review the diff, and commit the generated output before deploying.

Generation commands:

```bash
npm run generate
npm run generate:deals
```

## Required Vercel Environment

Set these in Vercel for Production before domain cutover:

- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`
- `ATHLETONIC_SITE_URL=https://athletonic.com`

Optional non-payment commerce settings:

- `ATHLETONIC_SHIPPING_AMOUNT_CENTS`
- `ATHLETONIC_FREE_SHIPPING_MIN_CENTS`
- `ATHLETONIC_SHIPPING_COUNTRIES=US`

Keep `.env`, `.env.*`, `.vercel/`, and service-role values out of git. Payment-specific Stripe variables are covered by the separate commerce/payment checklist.

## Domain Cutover

- Add `athletonic.com` and `www.athletonic.com` to the Vercel project.
- Configure DNS exactly as Vercel reports for the apex and `www` host.
- Keep `https://athletonic.com` as the canonical site origin unless the brand decision changes.
- Configure Vercel domain redirect behavior so the non-canonical host lands on `https://athletonic.com`.
- Confirm Vercel has issued valid HTTPS certificates for both hosts.
- Confirm `ATHLETONIC_SITE_URL` matches the canonical production origin with no trailing slash.

## Static SEO Assets

- `robots.txt` should allow public pages, disallow `/api/` and `/pages/admin/`, and point to `https://athletonic.com/sitemap.xml`.
- `sitemap.xml` should use `https://athletonic.com` URLs and current `lastmod` values.
- `robots.txt` and `sitemap.xml` are generated by `scripts/generate-home.mjs`; commit them when they change.
- Add a favicon and web app manifest before final brand launch if they are still absent.

## API Smoke Checks

Run these against a preview deployment first, then production after cutover:

- Public static pages load with 200: `/`, `/pages/catalog.html`, `/pages/contact.html`, and several product pages.
- API endpoints return JSON and `Cache-Control: no-store`.
- Admin API routes reject unauthenticated requests.
- Admin login loads and an authorized admin can reach the dashboard.
- Order lookup and return request endpoints reject invalid input without leaking internal details.
- Security headers are present on static and API responses: `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, and `Permissions-Policy`.

## Artifact Hygiene

- Confirm deploy source does not include `.env*`, `.vercel/`, `node_modules/`, `output/`, local virtualenvs, logs, or scraper artifacts.
- Confirm `data/athletonic-catalog.json` and `data/search-index.json` are valid JSON and match the intended catalog.
- Run `git status --short` before deployment and make sure all intended generated files are tracked.
- Do not deploy from a branch with unrelated unfinished storefront or API edits unless those edits are intentionally part of the release.

## Pre-Deploy Commands

```bash
npm test
node --check scripts/generate-home.mjs
node --check scripts/deals-engine.mjs
node -e "const fs=require('fs'); for (const f of ['package.json','vercel.json','data/athletonic-catalog.json','data/search-index.json']) JSON.parse(fs.readFileSync(f,'utf8'))"
git diff --check
```

Optional Vercel CLI check after pulling production env locally:

```bash
vercel pull --yes --environment=production
vercel build --prod
```

Do not treat checkout as production-ready until the separate Stripe/payment checklist passes.
